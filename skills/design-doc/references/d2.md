# D2 for design docs

desk draws every ```d2 block, and every .d2 file, as an SVG in both of its themes, in Linear's look: grey boxes, thin grey lines, small corners, a mono font, upright labels, no colour. It puts one line of d2 before the diagram (`look()` in apps/server/src/render.ts) and runs `d2 --pad=16 --theme=200` for dark and `--theme=0` for light, so write the diagram plain and leave the look to desk; an error's line number is still the diagram's own. A word after the fence's `d2`, as in ```` ```d2 Today ````, is the picture's caption, which desk writes above it in small grey; blocks that follow one another make a row, each picture side by side with the next while both still read, one under the other when not. Everything below was checked with d2 v0.8.1 on 15 Oct 2026.

Contents: the basics, eight patterns, pitfalls, checking.

## The basics

```d2
direction: right
you: You {shape: person}
plan: "The plan\ndirection + done-check"
agents: "Agents\nmany, long-running" {style.multiple: true}
cloud: "Cloud\nlater" {style.stroke-dash: 3}
you -> plan: sets
plan -> agents: carried out by
agents -> cloud: runs on {style.stroke-dash: 3}
```

- A shape is `id: Label`, and a connection is `a -> b: label` (also `<-`, `<->`, `--`). Ids are short words; the label is what shows.
- `direction: right` or `down` on the first line sets the flow.
- `\n` breaks a line inside a double-quoted label. Use it to put a role under a name: `"Review\nresult next to its plan"`.
- Shapes that carry meaning: `person` for the user, `diamond` for a decision, `cylinder` for stored data, `queue`, `page` for a document, `cloud`.
- Two styles carry meaning: `style.stroke-dash: 3` for what is later, optional or a side path (a twist, a dotted "when you look"), and `style.multiple: true` for many of one thing (agents, sessions).
- No colours. desk renders each diagram in a dark and a light theme, and its look picks every colour; a hand-set fill fights one of them. A `sql_table`'s constraint, such as `+ new`, shows in bright text over its dim columns, and a Markdown table's **bold** cell stands out over the plain ones, which is how a change stands out.
- A container groups shapes: `screen: The screen { board: Board; review: Review }`. Connect into it with a path: `you -> screen.review`.

## Eight patterns

**1. A loop or workflow**, flowing right. The steps as shapes, the step that sends you back dashed.

```d2
direction: right
understand: "1. Understand\nwhat is it really?"
plan: "2. Plan\npick one, note why"
do: "3. Carry out\nagents, many at once"
back: "4. Look back\ndid it work?"
understand -> plan -> do -> back
do -> plan: a twist {style.stroke-dash: 3}
```

**2. System context**, flowing down. The user as a person, the parts as shapes, what is later dashed, a container for one screen.

```d2
direction: down
you: You {shape: person}
chat: "Chat with Claude\nunderstand + plan"
agents: "Agents\nmany, long-running" {style.multiple: true}
screen: The screen {
  board: "Board\nneeds you first"
  review: "Review\nresult next to its plan"
}
you -> chat
chat -> agents: the plan
agents -> screen.board: state
agents -> screen.review: results
screen -> you: when you look {style.stroke-dash: 3}
```

**3. A screen's layout**, as a grid: separate things placed in rows or columns, never a table's cells (pattern 7). `grid-rows: 1` lays the children out left to right in one row, and `grid-columns: 1` stacks them in one column. A grid of more than one row and more than one column fills in an order of its own: read "A grid fills its columns first" under Pitfalls.

```d2
grid-columns: 1
board: "Board" {
  grid-columns: 3
  c: "1. Problem C\nneeds you"
  d: "2. Problem D\nto review"
  a: "3. Problem A\nrunning"
}
review: "Review: problem D" {
  grid-columns: 1
  p: "The plan"
  r: "The result"
}
```

**4. Who does what, in order**: a sequence diagram. Declare the actors first, in their left-to-right order. A container inside it is a group (a loop, an alternative); the actors named inside it are the same lanes, not new ones. `a -> a` is a step one actor does alone.

```d2
shape: sequence_diagram
you: You
desk: desk
session: The session
you -> desk: Hand off
desk -> session: carry out the plan
work: Until done {
  session -> session: build, commit, test
}
session -> desk: result.md
desk -> you: In review
```

**5. A decision**, with a diamond and labelled ways out.

```d2
direction: down
result: result.md
q: "has a ## Details heading?" {shape: diamond}
card: "The card, above Approve"
full: "The whole file, as today"
result -> q
q -> card: yes
q -> full: no
```

**6. The plan: the thing, Today and After**, two blocks one after the other, the part being worked on with a double border. Each is a picture of its own, so neither shrinks to make room for the other, and the page puts them side by side when both still read. One diagram holding both, as `today` and `after` containers in a grid, shrinks the pair as one: on 30 Oct a wide pair stacked that way drew its text at 6px. Not the progress: that is a few words in the report (or a plan.md's Now line).

```d2 Today
submit: Submit
charge: "Charge\nmodel credits"
submit -> charge
```

```d2 After
submit: Submit
charge: "Charge\nmodel credits + fee" {style.double-border: true}
total: "One total\na period" {shape: cylinder}
submit -> charge -> total
```

**7. A table of rows and columns**, such as cases, roles or states: one shape whose label is a Markdown table, written between `|||md` and `|||`, a header line, a `|---|` line, then one line per row. d2 draws it as one real table, a bold header row and lines between the cells. Mark the cell the part changes in **bold**, since a double border takes only a whole shape, and write that cell in words, such as **yes** or **Support login only**: a symbol such as ✓ or ✗ is missing from d2's mono font, so it draws from a fallback font, the same bold or not (3 Nov, on a test desk: a session's **✓** looked like every other ✓); to mark the whole table, put it in a container with the double border, as a `sql_table` below. In Today and After, the After table bolds what it adds or changes. Never build a table out of a grid of boxes, one per cell: each cell comes out a box of its own, and d2 fills a grid column by column, so the cells land out of place (3 Nov: the roles table of "Admin permissions", 24 boxes in `grid-columns: 4`; the user: "table is broken in d2. it looks... scattered"). desk refuses a step or a section holding one, a grid of two or more rows and columns of 6 or more unjoined boxes, a third of them one line, with a 422 naming the block's line.

```d2
roles: |||md
  | kind | supporter | editor |
  |---|---|---|
  | Look | yes | yes |
  | Model configs | no | **yes** |
  | Move money | no | no |
|||
```

**8. Today and After, a database table.** `shape: sql_table` draws each field as a row, name then type; a `constraint` shows at the row's end, so mark a new column with one. It holds two cells a row, so it also suits pairs, a name and what goes with it; three or more columns are a Markdown table (pattern 7).

```d2 Today
users: users {
  shape: sql_table
  overage_limit: int
}
```

```d2 After
users: users {
  shape: sql_table
  overage_limit: int
  byok_period_fee: int {constraint: "+ new"}
}
```

## Pitfalls

Quote a label that holds any punctuation besides a colon. Unquoted, these break, and the first two do it silently:

| Unquoted | What d2 draws | Why |
|---|---|---|
| `a: issue #12` | "issue" | `#` starts a comment |
| `a: plan; then build` | two shapes, "plan" and "then build" | `;` ends a statement |
| `a: the {slug} page` | nothing; it does not compile | `{` opens a map |
| `a -> b: result.md: the card` | "result.md: the card", as meant | a colon in a label is fine |

Two names d2 keeps for itself, both of which broke diagrams of the step-diagrams issue (27 Oct): `steps`, `layers` and `scenarios` cannot be a shape's id inside a container ("steps must be declared at a board root scope"), so name a list of steps `list`; and `style.double-border` takes only a rectangle, square, circle or oval, so a `page` or `cylinder` being worked on stays plain.

`a: "issue #12; the {slug} page"` draws exactly that.

Double quotes do not protect a `$`: `a: "cost $18"` does not compile ("substitutions must begin on {"), because `$` starts a variable there. Use single quotes, `a: 'cost $18'`, or escape it, `"cost \$18"`; both draw "cost $18" (d2 v0.8.1, 16 Oct 2026).

- d2's own keywords can't be ids: `shape: "Shape"` or `steps: "Steps"` fails ("reserved keywords are prohibited in edges", "edge with board keyword alone doesn't make sense"); so do `layers` and `scenarios`. Name it `form` or `stp` instead (27 Oct).
- A grid fills its columns first. With `grid-columns: 2` alone, d2 fills the first column top to bottom, then the second: six children a to f come out as `a d / b e / c f`, not `a b / c d / e f`. `grid-rows: 3` alone fills row by row, and with both set the one written first decides. On 28 Oct a two-column grid of pairs, each piece leaving the chat's head and where it still is, came out with every pair split across two rows; the user: "isn't the diagram looks wrong?". Pairs, a name and what goes with it, are a table: draw them as a `sql_table` (pattern 8), each row `"working dot": "the chat's Working… line"`, and three or more columns as one Markdown table (pattern 7), never as a grid of boxes. For separate boxes in rows, write `grid-rows` first (d2 v0.8.1, 28 Oct 2026).
- A container's own `direction` is ignored: desk's layout lays every container out in the top level's direction (27 Oct: `c: { direction: right; a -> b -> c }` under `direction: down` stacks a, b and c downward).
- `style.double-border` takes only rectangles, squares, circles and ovals: on a `sql_table` it fails to compile. To mark a table being worked on, put it in a container and give the container the double border: `kept: "kept on the step" {style.double-border: true; step: step {shape: sql_table; ...}}` (d2 v0.8.1, 31 Oct 2026).
- Keep a diagram to about a dozen shapes. Past that, split it into one overview and one diagram per part.
- A quoted label is plain text: `**` and links show as typed. Markdown draws only in a `|||md` block, which holds a table (pattern 7); put emphasis and links in the prose under the diagram.
- A Markdown table needs three pipes, `|||md` and `|||`: a single `|md` ends at the table's first `|`, and fails ("block string must be terminated with |", d2 v0.8.1, 3 Nov 2026).
- A diagram may run wider than the text column in desk, so a label of three to six words per line stays readable.

## Checking

```bash
python3 ~/.claude/skills/design-doc/scripts/check_d2.py <file.md>
```

It compiles each block as desk does, prints any that fail with its line and d2's error, and exits 1 if one did. It cannot catch the silent pitfalls above, so read the labels against that table too.
