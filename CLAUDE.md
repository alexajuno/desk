# desk

desk is the user's own vibe-coded workspace, TypeScript end to end in one pnpm workspace: a React app (`apps/web`: React, MobX, React Router, built with Vite) on a Node server (`apps/server`: Fastify, with the issues in Postgres through PGlite, inside the process). Every page address answers with the app, which reads its data from `/api/page/...` and gets each change pushed over `/api/sync`; the agents' JSON API (`/api/issues`...) is the one the desk skill documents. Node runs the server's `.ts` files as they are, with no build step. When desk starts, it installs packages if `pnpm-lock.yaml` changed (`apps/server/src/main.ts`) and builds the app if `apps/web` changed (`apps/server/src/web.ts`). Check types with `pnpm --filter server check`. The Python server it replaced (`desk/`, FastAPI) left the tree on 17 Oct and lives in git history. Its design doc is a file of the desk issue: `~/.local/share/desk/issues/desk/design.md`; the move to this stack is planned on the issue "desk on Linear's stack".

## Working on desk's code

- Never edit the main checkout, `~/projects/desk`. The user's app runs from it on port 8790, and an edit there breaks the app mid-change (14 Oct: a half-done rename did exactly that).
- Work on a feature branch in its own worktree, inside the checkout's `.claude/worktrees/`, which git ignores: `git -C ~/projects/desk worktree add .claude/worktrees/<name> -b feat/<name>`, then `pnpm install` inside it. Not `~/worktrees`, which the user cleared on 15 Oct: "desk will handle the dir". Never link `node_modules` (or anything) to the main checkout's: on 14 Oct git committed such a link for Python's `.venv`, and the merge replaced the real one with a link to itself.
- Test in the one desk on 8790, never in a copy ("only a single instance of app runs. wanna test requires switching to the main dir, which has the running instance", the user, 15 Oct): put the main checkout on your branch's commit through desk, naming your issue: `curl -s -X POST http://127.0.0.1:8790/api/issues/<slug>/try --json '{"branch": "feat/<name>"}'`, then wait until `/version` answers. desk detaches `~/projects/desk` on the branch, notes the issue so the sidebar's Trying names it, and restarts. Don't `git checkout --detach` by hand: the sidebar then shows only the branch, and the user can't tell which issue it is (15 Oct). Only a session with no issue does that, while the checkout is on main, then `systemctl --user restart desk`. It runs on the user's real data: trash any issue you made for the test.
- A change too big to try in the desk the user works in, such as the move to TypeScript, runs first on a second desk, on a copy of the data ("while developing, to confirm things work, could spin up another server... i wanna keep using the current desk", the user, 16 Oct): in your worktree, `DESK_DATA=<a copy of ~/.local/share/desk> PORT=8791 DESK_CLOCK=0 node apps/server/src/main.ts`. `DESK_CLOCK=0` keeps its line and its Slack connection off, which would otherwise act on the user's real checkout, and file the user's 🐧 tags into the copy; `DESK_LINE_REPO=<a throwaway repo>` runs its line there. Then try it on 8790 as above before landing.
- One branch at a time, in line ("allowing that session to resume to testing and get to review state without me manually watching", the user, 15 Oct):
  - When another branch runs on 8790, try answers that you are queued. End your turn then: desk messages you once your branch runs, and you carry on.
  - Hold 8790 only while you test. Once you have your screenshots, give it back with `curl -s -X POST http://127.0.0.1:8790/api/issues/<slug>/back-to-main`, which hands it to the next in line. desk takes it back on its own once your turn ends.
  - If your branch stops desk from starting, `git checkout main` in `~/projects/desk` and restart desk; the line moves on.
- An issue's session, which desk starts in `~/projects/desk` and the user talks to in the chat docked beside the issue, works in a worktree as above, and holds its work there until the user approves it:
  - When it is done, it has given 8790 back, and writes its card. The user presses Try on the issue to run its branch on 8790 (desk remembers the branch from the test), so the card's Try it starts with "press Try".
  - Approve in desk tells it to land on main. If main moved since the branch began, rebase onto main in the worktree, check the path again and land, with no second review ("after approve, and rebase, should merge immediately", the user, 15 Oct). How depends on where `~/projects/desk` stands:
    - On main: `git merge --ff-only feat/<name>` there, then `systemctl --user restart desk`.
    - On no branch, a test or the user's Try: leave it alone, and fast-forward main from your worktree with `git fetch . feat/<name>:main` (git allows it while main is checked out nowhere, and only as a fast-forward). Then call back-to-main: when it runs your branch, desk puts it on main, now with your work, and hands it on.
    - Then remove the worktree and the branch, and tell desk it landed, with the call Approve's message gives: desk reads no **Landed:** line from result.md.
  - When the user throws the work away instead, call back-to-main, which also takes you out of the line, and remove the worktree and the branch.
  - A session desk started before 15 Oct in a worktree it made (`claude -w`, branch `worktree-desk-<slug>`) cannot run git in `~/projects/desk`. It tests with `curl -s -X POST http://127.0.0.1:8790/api/issues/<slug>/try` (and `/back-to-main`), and desk merges it on Approve.
- A session you run yourself, outside desk: when the path you changed works on 8790, merge without asking ("when done testing, just merge", the user, 14 Oct), as above.
- Sessions run in the session host (`apps/server/src/host.ts`, through the Agent SDK), a process of its own that desk starts in a systemd scope (`desk-host-<port>-*.scope`), so that desk's restarts leave running turns alone; its log is `~/.cache/desk/host-<port>.log`. The host tells desk each turn's start and end, each question waiting, and each process's end over a WebSocket to `/api/host`, and desk keeps that in the `sessions` table (`turns.ts`), which the Inbox and the sidebar read. desk swaps it for one of newer code once its sessions have been quiet for ten minutes (`hosted.ts`). To force it, `systemctl --user stop 'desk-host-8790-*'`, which ends every session's process; each resumes on its next message.
- The app on 8790 is desk.service: restart it with `systemctl --user restart desk`, never with `fuser -k` plus `nohup node`, which leaves a desk outside the service holding 8790 while desk.service crash-loops on "address already in use" (15 Oct: 429 restarts, and every running session killed).
- Stop any other server by its port (`fuser -k <port>/tcp`), not with `pkill -f`, whose pattern also matches the shell running it.
- Pace: test the path you changed, screenshot it, merge, move on.

## Data

- Issues live outside the repo, in `DESK_DATA` (default `~/.local/share/desk`, its own git repo), so code work and merges never touch them.
- Postgres is the record of desk's state, in `DESK_DATA/.db`, whose own `.gitignore` keeps it out of the data repo: issues, teams and projects, the Inbox's rows and what you read of them, the trash, pins, each session's model, settings, Slack's tags and the 8790 line (19 Oct: "you should find whatever represent state, should be in db"). Each `issue.md`, `team.md` and `project.md` is only written out, on every save, for agents, git and an editor to read: one edited by hand changes nothing, and the next save writes over it. desk reads them in only into a database with no issues, a new or lost one. Change issues through the API.
- pins.json, session-models.json, settings.json and slack.json in `DESK_DATA`, and `desk-line` and `desk-trying` in the checkout's git dir, are copies desk still writes out for branches from before 19 Oct, and reads back at start only when such a branch changed them while Try ran it (`apps/server/src/copies.ts`). Never edit them, and never read desk's state from them.
- An issue's body is its one document, `## Context`, `## Plan` and `## Result` (19 Oct: "seemingly we don't need multiple files"), and every writer goes through the API: a session sends a section with `PUT /api/issues/<slug>/sections/<name>`, and the page's editor sends the document it started from, so a section it left as it was keeps what a session wrote meanwhile (`issues.ts`, "the document"). Only screenshots stay files, in the issue's folder. An older issue's `plan.md` and `result.md` still show while its document lacks the section. A session asks its questions in its chat.
- Every write to a table the app holds (issues, teams, projects, chats and the Inbox's rows so far) goes through `db.write` in `apps/server/src/db.ts`: one transaction, in which a trigger numbers each changed row in the log, `changes`, and `/api/sync` sends the app what was logged. Never write those tables through `sql()`. A table the app should hold joins `HELD` there, which gives it its trigger.
